# ريفرسايد PMS — تمرين هندسي

[English](README.en.md)

خدمة صغيرة لإدارة عقار فندقي من ١٢ غرفة: التوفّر، عروض الأسعار، الحجوزات، كشوف الحسابات
والإلغاءات. الخدمة تعمل في الإنتاج منذ سنة.

هناك بلاغان مفتوحان عليها. تجدهما في [`TICKETS.md`](TICKETS.md)، ومقتطفات السجلات في
مجلّد [`logs/`](logs/). قواعد العمل التي يتوقّعها الفندق موجودة في [`SPEC.md`](SPEC.md)،
وعند أي اختلاف بين الكود والمواصفة فالمواصفة هي المرجع.

## التشغيل

لا حاجة لتنصيب قاعدة بيانات — المخطّط والبيانات الأولية
تُحمَّل في قاعدة SQLite داخل الذاكرة عند الإقلاع، فكل إعادة تشغيل تمنحك نظامًا نظيفًا ومطابقًا.

```bash
docker compose up                          # http://localhost:3000
docker compose run --rm pms npm run verify # تشغيل الملف المرجعي داخل الحاوية
```

أو بدون Docker — يتطلّب Node إصدار 22.5 أو أحدث:

```bash
npm install
npm start          # http://localhost:3000
npm test           # مجموعة الاختبارات الحالية
npm run verify     # إعادة تشغيل الملف المرجعي (انظر أدناه)
```

## الملف المرجعي

يحتفظ قسم المالية بتصدير يضمّ 596 صفًا من عروض الأسعار وعمليات البحث عن التوفّر ومعاينات
التعرفة، مأخوذة من النظام السابق، في `fixtures/expected.csv`. يعيد الأمر `npm run verify` تشغيلها
جميعًا على هذه الخدمة ويُبلغ عن كل صف يختلف فيه النظامان. يمكنك حصر النتائج بنوع واحد:

```bash
npm run verify -- QUOTE
```

## ما نودّ استلامه

1. **`FINDINGS.md`** — التقرير. لكل بلاغ:
   - كيف أعدتَ إنتاج المشكلة، وأصغر مُدخل يُظهرها؛
   - السبب الجذري: الآلية نفسها، لا إعادة صياغة للعَرَض؛
   - لماذا لا يكون الإصلاح الواضح المكوّن من سطر واحد هو الإصلاح الصحيح — سمِّه صراحةً؛
   - كل ما تأثّر بالسبب نفسه؛
   - ما الذي حصّنته حول الإصلاح، ولماذا؛
   - وما الذي قرّرت تركه دون تغيير، ولماذا.
2. **الإصلاح**، بالصورة التي كنت ستدفعه بها إلى الإنتاج.
3. **اختبارات انحدار** تفشل قبل تغييرك وتنجح بعده.
4. في `FINDINGS.md` أيضًا، أجب: **ما صفوف الملف المرجعي التي كانت فاشلة قبل إصلاحك؟**
   يكفي ذكر المعرّفات والعدد.


## إن استعنت بالذكاء الاصطناعي

استخدام أدوات الذكاء الاصطناعي **مسموح تمامًا** ولا يُنقص من تقييمك شيئًا.

لكن إن استعنت بها في أي جزء من هذا العمل، أرفق ملف **`AI-CONVERSATION.md`** يتضمّن
**المحادثة كاملة كما جرت**: كل ما كتبته وكل ما ردّ به النموذج، بالترتيب، دون حذف ولا تلخيص
ولا تنقيح. وإن استخدمت أكثر من أداة أو أكثر من جلسة، أدرجها جميعًا تحت عناوين واضحة.

وإن لم تستعن بها إطلاقًا فاكتب ذلك في سطر واحد داخل الملف نفسه.

نقرأ هذا الملف لنفهم كيف تفكّر: متى تقبل اقتراحًا ومتى تردّه ولماذا — لا لنحاسبك على استخدام
الأداة. أما إخفاء الاستعانة بها أو تقديم نسخة منقّحة من المحادثة فيُنهي التقييم.
