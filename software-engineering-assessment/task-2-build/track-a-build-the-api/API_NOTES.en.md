# What the storefront asks for

[بالعربية](API_NOTES.en.md)

The storefront in `frontend/` is already built. These are the calls it makes, written out
as examples taken from a working session. Anything not shown here it does not use.

Every request except `POST /auth/login` carries `Authorization: Bearer <token>`.
Responses are JSON.

## Errors

Any response that is not a 2xx is expected to look like this. The storefront shows
`error.message` to the customer as-is.

```json
{ "error": { "code": "SOMETHING", "message": "Sorry, that coupon has expired." } }
```

A `401` from any endpoint signs the customer out and returns them to the sign-in screen.

## Sign in

```
POST /auth/login
{ "username": "salma", "password": "correct-horse-9" }

200
{ "token": "...", "user": { "id": "u_salma", "username": "salma", "displayName": "سلمى الحسيني" } }
```

```
GET /auth/session

200
{ "user": { "id": "u_salma", "username": "salma", "displayName": "سلمى الحسيني" } }
```

```
POST /auth/logout
{}

200
{}
```

The storefront calls `GET /auth/session` when it loads, and `POST /auth/logout` from the
menu.

## Cart

```
GET /cart

200
{
  "items": [
    { "id": "ci_7", "productId": "p_002", "sku": "KTL-COP-02", "name": "إبريق تقطير نحاسي",
      "price": "89.50", "quantity": 2 }
  ],
  "coupon": "SAVE10",
  "discount": "17.90"
}
```

`items[].id` is the cart line, not the product. The storefront uses it for `PATCH` and `DELETE`.
`coupon` and `discount` are `null` and `"0.00"` when no coupon is applied.

Adding an item sends the product as the storefront received it from `GET /products`, with a
quantity attached:

```
POST /cart/items
{ "id": "p_002", "sku": "KTL-COP-02", "name": "إبريق تقطير نحاسي", "category": "kitchen",
  "price": "89.50", "stock": 12, "imageUrl": "/img/kettle.jpg", "description": "فوهة رفيعة منحنية، سعة لتر واحد.",
  "quantity": 1 }

201
{ "id": "ci_7" }
```

```
PATCH /cart/items/ci_7
{ "quantity": 3 }

200
{ "id": "ci_7", "quantity": 3 }
```

```
DELETE /cart/items/ci_7

204
```

```
POST /cart/coupon
{ "code": "SAVE10" }

200
{ "coupon": "SAVE10", "discount": "17.90" }
```

## Checkout

```
POST /orders
X-Request-Id: 6d1f0e7c-1d2a-4a1e-9a1c-4b7f5a2e0c11

{
  "coupon": "SAVE10",
  "card": { "name": "سلمى الحسيني", "number": "4242424242424242", "expiry": "12/29", "cvc": "123" },
  "summary": { "subtotal": "179.00", "discount": "17.90", "total": "161.10" }
}

201
{ "id": "o_1042", "status": "paid", "total": "161.10", "createdAt": "2026-08-19T10:14:02Z" }
```

`summary` is what the customer saw on the payment screen. `X-Request-Id` is generated by the
storefront and travels with the request.

After a successful checkout the storefront sends the customer to `#/orders/{id}`.

## Orders

```
GET /orders

200
{
  "items": [
    { "id": "o_1042", "status": "paid", "total": "161.10", "createdAt": "2026-08-19T10:14:02Z" }
  ]
}
```

```
GET /orders/o_1042

200
{
  "id": "o_1042",
  "status": "paid",
  "total": "161.10",
  "createdAt": "2026-08-19T10:14:02Z",
  "items": [
    { "productId": "p_002", "name": "إبريق تقطير نحاسي", "quantity": 2, "price": "89.50" }
  ]
}
```

The order page is a normal address: `http://localhost:8080/#/orders/o_1042`.
