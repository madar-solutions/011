# المسار (أ) — بناء الواجهة الخلفية للمتجر

[English](README.en.md)

مجلّد `frontend/` يحتوي متجرًا إلكترونيًا مكتملًا، لكن بلا واجهة خلفية. مهمتك بناء واحدة.

- يجب أن تخدم الاستدعاءات الموثّقة في [`API_NOTES.md`](API_NOTES.md).
- حمِّل [`seed.json`](seed.json) — فيه المستخدمون والمنتجات وأكواد الخصم.
- نفّذ الدفع بالبطاقة عبر بوابة الدفع في [`payments-mock/`](payments-mock/README.md).
- أي لغة أو إطار عمل أو قاعدة بيانات تختارها.
- أضف خدماتك إلى `docker-compose.yml`. ويجب أن يُشغّل الأمر `docker compose up` من نسخة
  نظيفة متجرًا عاملًا على http://localhost:8080.
- تعامل معه ككود ستدفعه إلى الإنتاج وتسلّمه لفريق.
- أرفق ملف README مختصرًا: كيف يُشغَّل، وما القرارات التي اتخذتها، وما كنت ستفعله لو توفّر وقت أطول.

المدة المقترحة **ست ساعات**، تعمل عليها في المنزل. سجّل تغييراتك في commits أثناء العمل.

## إن استعنت بالذكاء الاصطناعي

استخدام أدوات الذكاء الاصطناعي **مسموح تمامًا** ولا يُنقص من تقييمك شيئًا.

لكن إن استعنت بها في أي جزء من هذا العمل، أرفق ملف **`AI-CONVERSATION.md`** يتضمّن
**المحادثة كاملة كما جرت**: كل ما كتبته وكل ما ردّ به النموذج، بالترتيب، دون حذف ولا تلخيص
ولا تنقيح. وإن استخدمت أكثر من أداة أو أكثر من جلسة، أدرجها جميعًا تحت عناوين واضحة.

وإن لم تستعن بها إطلاقًا فاكتب ذلك في سطر واحد داخل الملف نفسه.

نقرأ هذا الملف لنفهم كيف تفكّر: متى تقبل اقتراحًا ومتى تردّه ولماذا — لا لنحاسبك على استخدام
الأداة. أما إخفاء الاستعانة بها أو تقديم نسخة منقّحة من المحادثة فيُنهي التقييم.


## تشغيل الأجزاء التي زوّدناك بها

```bash
docker compose up
```

المتجر على http://localhost:8080 ويتصل بما يشير إليه المتغيّر `API_BASE_URL`
(القيمة الافتراضية `http://localhost:3000`). وبوابة الدفع على http://localhost:9090.
